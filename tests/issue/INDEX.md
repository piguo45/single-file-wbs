# テストJSON 一覧

データの形は **v0.2（`projects[].issues`）** の1本だけ。課題側は v0.2 が最初の公開形で、
旧形式（`sheets[]` / トップレベル `issues` / `decision` / `pending.reason` / 課題レベル `assignee` /
`actions[].wbs`）の読み替えは**持たない**（作者裁定 2026-09-09）。fixture も全部新形式。

ファイル名の接頭辞で期待表示が分かる：
- **`正常_`** … 正しく描画される（崩れたら不具合）
- **`異常_`** … 壊れた/境界の入力。**表示は degraded（崩れて当然）だがクラッシュしないこと**を確認するもの

E2E の本日は `../e2e_issue/common.py` の `CLOCK_PIN`（**2026-09-15**）で固定している。
期限超過や★（＝「更新」の印）の既定期間（＝本日を含む直近7日＝**9/9〜9/15**）など「本日依存」の期待値はこの日付を前提に書いてある。

## 異常系（表示は崩れる・クラッシュしないことを確認）
| ファイル | わざと壊した内容 / 期待表示 |
|---|---|
| 異常_不正な日付.json | 形式外・1900〜2099外・数値/真偽/オブジェクト → 無視して `—`・(調整中) |
| 異常_enum不正.json | `priority` が3値以外/数値 → **mid 扱い**。`pending.kind` が既知値以外 → **印を出さない**（`pending` が無いものとして描く）。`closed.how` が既知値以外 → **サブ表示なし**の完了 |
| 異常_欠損フィールド.json | `id`/`title`/`actions`/`note` 欠損・`decisions`/`pending`/`closed` が非オブジェクト・文字列欄が数値 |
| 異常_actions非配列.json | `actions` が文字列/オブジェクト/数値 → 丸ごと無視。要素に `null`/数値/文字列/配列が混ざる → 要素ごとに無視 |
| 異常_projects不正.json | `projects` の要素が `null`/数値/文字列/配列 → 要素ごと無視。`issues` 非配列・`name` 欠損の案件 → 0件・`(名前なし)` 表示。`projects` 自体が非配列のケースは `test_corpus.py` の inline で併検 |
| 異常_リンク不正.json | `links[]` の壊れ：存在しない WBS／課題／案件名・`http(s)` でない URL → **薄い取り消し線＋ツールチップ**。`links` 非配列・要素が非オブジェクト → 無視。`title`/`project` への属性インジェクション |
| 異常_非オブジェクトトップ.json | トップが数値 → 空表示（null/配列/文字列は `test_corpus.py` の inline で併検） |
| 異常_id重複.json | 同じ `id` が2件 → **折りたたみキーが衝突するのは仕様**（§3.5）。落ちないことだけを見る |
| 異常_計画の型崩れ.json | 同じ案件の **計画側（`tasks`／`milestones`）が壊れている**（非配列・要素が数値/null・`children` が非配列）→ **計画は無視するが消さない**（保存で壊れた要素も残る）・**課題側はそのまま読める**（`test_broken_plan.py`） |
