# E2E テスト（headless Chromium / Playwright）

統合ビューア `wbs_viewer.html` の**課題側**の描画・導出・絞り込み・編集・保存・権限フローを headless Chromium で検証します。
File System Access API はフェイクハンドルで模擬しているため、**実ファイルには一切書き込みません**。

> 注: ここで使う Playwright は**テスト専用の開発ツール**です。製品本体 `wbs_viewer.html` は依存ゼロ（ライブラリ/CDN/ビルド不要）のままです。

## 実行方法（uv・推奨）

リポジトリ直下の `pyproject.toml` で依存（playwright）を管理しています。

```bash
uv sync                                  # 初回のみ：.venv を作成（playwright 等を導入）
uv run playwright install chromium       # 初回のみ：headless Chromium を取得
uv run python tests/e2e_issue/run_all.py       # 全スイート（1つでも赤なら FAILED）
uv run python tests/e2e_issue/test_render.py   # 個別スイート
```

<details><summary>uv を使わない場合（pip）</summary>

```bash
pip install playwright && playwright install chromium
python tests/e2e_issue/run_all.py
```
</details>

決定論化：本日依存（期限超過・決定/保留/完了の記録日・＋課題の起票日・**★（更新）の既定期間**）は
`common.CLOCK_PIN`（**2026-09-15** 固定）で固定しています。実行日が変わってもテストはドリフトしません。
★（更新期間）の既定は「本日を含む直近7日」なので、固定本日では **9/9〜9/15** になります。

## 追加するときの作法

- **本日に依存する期待値は必ず `CLOCK_PIN` 基準で書く**（実行日を使わない）。
- **性能の断言は「5 回計って中央値」で見る**（`test_projects.py` の `PERF_N`）。
  最大値は負荷のスパイクを拾って赤くなるので、`[実測]` 行の情報として出すだけにする。
- **リロードを伴う「記憶」の検証は `pg.reload()` ではなく `reload(pg)`（`common.py`）を使う。**
  file:// ＋ 新しい BrowserContext では localStorage がメモリ上にしか無く、
  リロードの隙に Chromium がストアごと捨てることがある（通しで回すと散発的に赤くなる。
  書き込みの遅れではない＝ブラウザ側へはリロード前に届いていることを CDP で確認済み）。
  `reload()` は消えたキーを書き戻して読み込み直す（消えた時だけ stderr に WARN を出す）。
  「同一オリジンの補助ページを開いたままリロードして参照を 0 にしない」も試したが、
  喪失率が 5%（2/40）→ 25%（10/40）と悪化したので採っていない。
  なお `reload()` は**リロード前に在ったキーが消えていたら書き戻す**ので、
  将来ビューアが「読み込み時にキーを消す」挙動を持ったらこのヘルパーを見直すこと。
- ファイル内容を読む前に**保存デバウンス（400ms）を待つ**（`flush()` 相当の待ち）。
  DOM は同期で更新されるが、ファイルへの書込は遅延する。
- **担当の入力欄は行動側（`input[data-a="N"][data-field="assignee"]`）にしかない。**
  課題レベルの `assignee` は廃止し、担当列も無い。担当が画面に出るのは
  「詳細の行動の行（`担当：○○`）」と「たたんだ時の次の一手1行」だけ。
- 開閉の判定は `td.detail .body` の有無で見る（本文があれば開いている）。
  表示モードでは `td.title` 自体に `data-tog` が付くのでセルのどこを押しても開閉できるが、
  **編集モードでは `td.title` 内の caret（`[data-tog]`）だけ**が開閉トリガー。
- タイトルの `input` と課題削除の `✕` は**タイトル列**にある（詳細列ではない）。
- **操作は実ポインタ（`page.click`）で押す。** `dispatch_event`/JS の `element.click()` は
  要素が他の帯に覆われていても通ってしまい、「タブが操作バーに食い込んで押せない」種の
  レイアウト事故を見逃す（実際に一度出した）。`test_projects.py` は低い画面（360/500px）でも
  `.stab` が `#tabBar` の内側に収まり、`#topbar` と重ならず、各タブ中心の
  `document.elementFromPoint` が自分自身であることを断言している。
  `dispatch_event` を使ってよいのはタブのダブルクリック（名前変更）だけ。
- 案件は**開いているものだけ DOM 化**する。行数の断言はそのまま「他案件を描いていない」証拠になる。
  タブは `#tabBar .stab`（サマリは `[data-summary]`・案件は `[data-si="N"]`）。
  折りたたみキーは `案件名|id` なので案件ごとに独立している。
- リンク行（`.lk`）のクリックは折りたたみに使わない。たたむ/開くを操作するときは
  `td.title b`（タイトルの文字）か `td.title .caret` を押す（`td.title` の中心はリンク行に当たることがある）。
- タブのダブルクリック（名前変更）は `dispatch_event(..., "dblclick")` で直接投げる。
  `dblclick()` は前置のクリックでタブバーが再描画され、ブラウザが dblclick を発火しないことがある。
- 詳細の中は「役割ごとに表現を1種類」：帯＝塗り／★＝黒の記号（`--star`）／済・未＝文字の濃淡。
  枠線は優先度・状態のバッジ専用なので、詳細の中の要素に `border-width` が付いたら回帰。
- 区切りの帯を数えるときは `.sec:not(.noteb)`。備考の印は同じ `.sec` の形を使い回している。
- 吹き出し（`#isForm` / `#notePop`）は `formEl` を共有＝**同時に1つ**。外側クリックの除外リストに
  トリガー（`[data-note]` 等）を足し忘れると、開いた瞬間に閉じる。
  en の済/未は `☑`/`☐`（13px・`align-self:center` で行の高さは ja と同じ 19.2px）。
- ★は「更新期間に動いたか」の導出（表示は `★ 更新 N`／`更新期間 9/1〜9/7`）。期間は `#starRange`（表示）／`#stat input[data-star="from"|"to"]`（編集）で見る。
  ★のある課題数は `#starCount`。期間を編集したあと導出表示を見るときは `blur()` → ~500ms 待つ。
- 編集の結果が**画面の導出値**に出たかを見るときは、`blur()` してから ~500ms 待つ
  （入力にフォーカス中は `deferRender` が再描画を遅らせるため）。
