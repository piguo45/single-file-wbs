### 2. 課題管理論の要点（記事から転記・スキーマはこれに従う）

- **課題**＝「起きてしまったこと（事象）」と「これから取り組むこと（改善）」の**合流点**。表には課題・TODO・問題が混在してよい。
- 行の性質は**完了条件の型**で読み分ける：
  - 方針が決まったら閉じる：課題・未決
  - 実行が終わったら閉じる：アクションアイテム・TODO
  - 表の外：リスク（起きたら課題に）・改善（取り組むと決めたら課題に）
- 管理＝4つの動き：**載せる → 決める → 組み込む → 閉じる**
  - **載せる**：二つの問い「**放置すると、いつ、何が起きるか**」「**やると、いつ、何が生まれるか**」の**どちらかに答えられるものだけ**載せる。答えから 期限・優先度・完了条件 が決まる。
    - 期限＝**影響が現れる日・価値を受け取りたい日**（担当者がいつやるかではない）
    - 優先度＝影響の大きさ × その日の近さ
    - 完了条件＝書いた弊害が起きない／書いた価値が実現したと確かめられた状態
  - **決める**：やるのか、やらないのか。「対応しない」と決めた行はここで閉じる。
  - **組み込む**：実行が必要な対応はアクションアイテムに分解して WBS へ。課題表が持つのは「**何を、なぜ**」、WBS が持つのは「**いつ、誰が、どうやって**」。同じことを両方に書かない。
  - **閉じる**：アクションアイテムが全部終わっても課題は自動では閉じない。**完了条件が満たされたことを確かめて**閉じる。期限が過ぎて何も起きなかった行は「**発生せず**」として閉じる（消さない）。
- **ペンディング**（進められない状態・横断的）：理由は3つで打ち手が違う。
  - 決まっていない（未決）→ 決められる人に持ち込む
  - 揃っていない（人・モノ・情報・時期）→ 相手に催促
  - 止めている（意図的凍結）→ 再開条件を書いて寝かせる
  - 理由が書かれていないペンディングは止まり続ける → **理由は必須**

## 3. データ形式 `issue.json`（v0.1・確定）

### 3.1 設計原則（wbs と同じ）
1. **事実だけを持つ**。状態（未決／対応中／保留／完了）・期限超過・★（どの行に付くか）は**すべてビューアが導出**し、JSONに書かない。
   - **例外は `star`**（★を付ける報告期間）＝派生値ではなく**設定**。報告する人と読む人・AIが同じ★を見るために JSON に持つ（2026-09-07 決定）。
2. **`_` 始まりはカスタムキー**（ビューアは無視・保存で保持・AIのメタ置き場）。
3. **スキーマはほぼ動かさない**。変える時は読む側の後方互換＋ `CLAUDE.md`/`CLAUDE.en.md` 同時更新。
4. 壊れた入力でも**クラッシュしない**（graceful degradation）。

### 3.2 形

```json
{
  "name": "自分の課題管理表",
  "star": { "from": "2026-09-01", "to": "2026-09-07" },
  "sheets": [
    {
      "name": "○○移行プロジェクト",
      "issues": [
        {
          "id": 1,
          "title": "移行テストで文字コード起因のエラーが大量発生",
          "priority": "high",
          "opened": "2026-09-05",
          "due": "2026-10-20",
          "ifIgnored": "本番の切替で同じエラーが起き、移行が失敗する。影響が出るのは本番切替日",
          "ifDone": "",
          "closeWhen": "リハーサルで一連の移行手順を通して、エラーが出ないこと",
          "decision": { "at": "2026-09-07", "text": "原因調査と変換処理の修正で対応する" },
          "pending": null,
          "closed": null,
          "actions": [
            { "date": "2026-09-05", "text": "事象発生", "assignee": "", "done": true },
            { "date": "2026-09-07", "text": "調査方針検討、影響調査", "assignee": "ぴぐお", "done": true },
            { "date": "2026-09-11", "text": "資料作成、内部Rv", "assignee": "ぴぐお/Aさん", "done": false },
            { "date": "2026-09-14", "text": "ツール作成、PT（9/14週）", "assignee": "ぴぐお", "done": false, "wbs": "2.3" },
            { "date": null, "text": "文字コード仕様について開発部と打合せ", "assignee": "", "done": false },
            { "date": null, "text": "移行リハーサル検証", "assignee": "ぴぐお", "done": false }
          ],
          "note": "https://example.com/spec ・関連リンクは note に素のURLで（自動リンク）",
          "_ai": { "tokens": 1200, "model": "claude-fable-5-1", "memo": "起票をAIが下書き" }
        }
      ]
    }
  ]
}
```

**従来形式（`sheets` なし）＝ `{ name, star, issues }` は「シート1枚のブック」として読む**（後方互換・タブバー非表示）。両方あれば `sheets` を優先。`star` は**ブック共通**（2026-09-07 決定）。

### 3.3 フィールド定義

| キー | 型 | 必須 | 意味（＝日常語） |
|---|---|---|---|
| `name` | string | 任意 | プロジェクト名（表のタイトル） |
| `star` | `{ from, to }` ｜ null | 任意 | **報告期間**＝★を付ける範囲（トップレベル）。`to` 省略＝本日。無ければ既定＝**直近7日**。設定であって派生値ではない（2026-09-07 決定） |
| `sheets[]` | array | 任意 | **シート（案件ごとの表）**＝ `[{ name, issues }]`。あれば `issues` より優先（2026-09-07 決定） |
| `sheets[].name` | string | 必須 | タブに出るシート名（案件名） |
| `sheets[].issues` | array | 必須 | そのシートの課題。**配列順＝表示順** |
| `issues[]` | array | `sheets` が無ければ必須 | 課題の配列（従来形式＝シート1枚のブック）。`sheets` があるときは読まれない |
| `id` | number（整数） | 必須 | No。**シート内で**一意。欠番可。**振り直さない**（シートをまたいで移すときだけ移動先で振り直す） |
| `title` | string | 必須 | 見出し（全角30字目安。詳細は他欄へ） |
| `priority` | `"high"｜"mid"｜"low"` | 任意（既定 `mid`） | 優先度＝影響の大きさ×期限の近さ。画面は 高／中／低 |
| `opened` | `YYYY-MM-DD` | 任意 | 載せた日 |
| `due` | `YYYY-MM-DD` ｜ null | 任意 | **期限＝影響が現れる日・価値を受け取りたい日** |
| `ifIgnored` | string | 二者択一 | 「放置すると、いつ、何が起きるか」（妨げる側の問い） |
| `ifDone` | string | 二者択一 | 「やると、いつ、何が生まれるか」（加速させる側の問い） |
| `closeWhen` | string | 必須（空でも可・空は警告表示） | **完了条件**＝弊害が起きない／価値が実現したと確かめられた状態 |
| `decision` | `{ at, text }` ｜ null | 任意 | **決める**：対応方針。`at`=決めた日、`text`=方針。null＝未決 |
| `pending` | `{ since, reason, detail, resumeWhen }` ｜ null | 任意 | **ペンディング**。`reason` は `"undecided"`（決まっていない）／`"missing"`（揃っていない）／`"frozen"`（止めている）。`detail`=何が／誰に。`resumeWhen`=再開条件（frozen で推奨） |
| `closed` | `{ at, how, note }` ｜ null | 任意 | **閉じる**。`how` は `"resolved"`（完了条件を満たした）／`"wontfix"`（対応しないと決めた）／`"not_occurred"`（発生せず）。`note`=確かめた事実 |
| `actions[]` | array | 任意 | 実績と予定（Excel の 実績／予定 の段）。**配列順＝時系列の表示順**。画面では `実績`／`予定` の帯で分ける |
| `actions[].date` | `YYYY-MM-DD` ｜ null | 任意 | 日付。**null＝調整中（未定）** |
| `actions[].text` | string | 必須 | 何をした／する |
| `actions[].assignee` | string | 任意 | その行動の担当（`"ぴぐお/Aさん"` のような複数表記は自由文字列）。**担当はここだけに持つ**（課題レベルの担当欄は無い・2026-09-06 決定） |
| `actions[].done` | boolean | 任意（既定 false） | 済／未。画面は文字の濃淡だけで分ける（済＝濃い灰の太字・未＝薄い灰／英語UIは ☑／☐） |
| `actions[].wbs` | string | 任意 | **組み込む**：`wbs_roadmap.json` のタスク id（例 `"2.3"`）。表示は小さなタグ `WBS 2.3` |
| `note` | string | 任意 | 備考（添え書き）。**常時表示しない**＝詳細末尾の `備考` の印から ホバー（ツールチップ）／クリック（吹き出し固定）で読む。`http(s)://` は自動リンクで**吹き出しの中で押せる**（2026-09-07 決定） |
| `_任意名` | any | 任意 | カスタムキー（ビューア無視・保存で保持） |

### 3.4 導出値（ビューアが計算・JSONに書かない）

| 導出値 | 規則 |
|---|---|
| **状態** | `closed` あり → **完了**（`how` で 解決／不対応／発生せず のサブ表示）／ else `pending` あり → **保留**（reason バッジ：未決・不足・凍結）／ else `decision` なし → **未決**／ else → **対応中** |
| **期限超過** | 本日 > `due` かつ 未完了 → `due` を赤字（完了行は赤にしない） |
| **★ 更新**（報告期間に動いたもの） | 期間内に**済んだ行動**（`done:true` かつ `date` が期間内・`date:null` は付かない）／期間内の `decision.at`（決めた）・`pending.since`（止めた）・`closed.at`（閉じた）に ★。★が1つでもある課題は**タイトルに ★**（たたんでも見える）。期間＝`star`（無ければ直近7日）。件数サマリに `★ 更新 N`（`⚠ 期限超過 N` と対）、メタ行に `更新期間 9/1〜9/7`（既定時は `更新期間 直近7日`）。タブ・タイトル・詳細行では ★ の記号だけ出し、ツールチップに「更新…」。2026-09-07 決定 |
| **次の一手** | `done:false` の最初の1件（サマリ・ツールチップに使う） |
| **たたんだ時の詳細列** | **次の一手**（`done:false` の最初の1件）を1行で表示：`未 9/11 資料作成、内部Rv 担当：ぴぐお/Aさん`。未の行動が無ければ**空欄**（完了の課題は常に空欄）。2026-09-07 決定・課題は担当欄を持たず、独立した担当列も持たない |
| **未回答の警告** | `ifIgnored` と `ifDone` が両方空／`closeWhen` が空 → 行に薄い警告マーク（「載せる」の規律を促す。エラーにはしない） |
| **件数サマリ** | ヘッダ右：未決／対応中／保留／完了 の件数・期限超過 N（完了込みで不変＝誠実なview） |

**「実行が終わったら閉じる」型（TODO的な行）の扱い**：載せた時点で `decision` を `{ at: 載せた日, text: "実施する" }` と書く（＝迷う余地がないので決定済み）。`decision` を空のままにすると「未決」と表示される＝これは仕様（未決を隠さない）。

### 3.5 異常系（wbs と同じ方針：無視・空表示・落ちない）
- 不正日付（形式外・1900〜2099外）→ 無視・`—` 表示
- `priority` が3値以外 → `mid` 扱い
- `pending.reason`／`closed.how` が既知値以外 → バッジ無しの「保留」「完了」
- `actions` が非配列／要素が非オブジェクト → 無視
- `sheets` が非配列／空／要素が非オブジェクト → 無視して従来形式（`issues`）を読む。`issues` も無ければ空表示
- `sheets[].name` 欠損 → 名前なしのタブとして描く（落ちない）
- `issues` 空／トップが非オブジェクト／`id` 重複 → 空表示・落ちない（重複 id は折りたたみキー衝突のみ）
- 不正 JSON → アラート（無言失敗しない）
- XSS：全ユーザー文字列は `esc()`。属性へ生値を流さない

## 4. 画面 `issue_viewer.html`（v0.1）

Excel `課題管理表.xlsx` の見た目を再現する。列＝ **No ／ 優先度 ／ タイトル ／ 詳細 ／ 状態 ／ 期限** の6列（2026-09-07 決定・A案。**タイトルが独立列**／担当列は無し）。
順番の意味は「左＝**何の話か**（No・優先度・タイトル）／中＝**どう進んでいるか**（詳細）／右＝**今どこか・いつまで**（状態・期限）」。
**折りたたみの `▼/▶` と未回答の `⚠` はタイトル列**に置き、**タイトルのセルのクリック**でたたむ／開く。全展開／全たたみの `▼/▶` はタイトル列の見出し。
担当は「**詳細の中の行動行**」と「**たたんだ時の詳細列の1行**」の2か所だけに、**`担当：ぴぐお`** の形で出す（空ならラベルごと出さない）。データには課題レベルの担当を持たない。
`sheets` があるときは表の上に**タブバー**を出す（先頭「**サマリ**」＋シートごとのタブ・タブ名の右に `★N ⚠N`）。
**サマリ**＝シートごとの集計表（シート名／未決／対応中／保留／完了／`★ 更新`／`⚠ 期限超過`／次の期限＋合計行。行クリックでそのシートへ移動）。
**描画は開いているシートだけ**。ブラウザのタブ名＝「`name` – Issue Viewer」（2026-09-07 決定）。
「詳細」セルは1課題1ブロック（Excel の1セル多段書きをそのまま構造化。**タイトルは列にあるので詳細では繰り返さない**）。
区切りの `概要`／`実績`／`予定` は**帯（ラベル）＝灰の塗り・枠なし**として描く（`■` などの記号は使わず、区切り線も引かない。2026-09-07 決定）。
**詳細の中は「役割ごとに表現を1種類」**：帯＝塗り／★＝**黒の記号**（琥珀色は廃止）／`済`・`未`＝**文字の濃淡**（済＝濃い灰の太字・未＝薄い灰）。英語UIは 済／未 を **☑／☐** にする（濃淡の規則は共通）。備考の印は**帯より薄い塗り**。**★は全箇所で黒**（行動行・タイトル・タブ・右上の `★ 更新 N`）。**枠線は優先度・状態のバッジ専用**で、詳細の中では塗り・枠・取り消し線・大きさの差を使わない（2026-09-07 決定）。
下のスケッチで行頭に置いた `概要` `実績` `予定` は、その帯を表す：

```
概要
  支障：<ifIgnored>        価値：<ifDone>（空なら行ごと省略・2026-09-07 に見出し語を変更）
  完了条件：<closeWhen>
  方針：<decision.text>（<decision.at>）   ← あれば
  保留：[不足] <detail>／再開条件：<resumeWhen>   ← あれば
  完了：[解決] <closed.note>（<closed.at>）   ← あれば
実績
      済  9/5   事象発生
  ★  済  9/7   調査方針検討、影響調査              担当：ぴぐお
予定
      未  9/11  資料作成、内部Rv                    担当：ぴぐお/Aさん
      未  9/14  ツール作成、PT（9/14週） [WBS 2.3]  担当：ぴぐお
      (調整中) 文字コード仕様について開発部と打合せ
  [備考]                                  ← 印だけ。ホバーで全文・クリックで吹き出し固定（中のURLを押せる）
```

### 4.1 土台（wbs から流用・必須）
- **単一HTML・依存ゼロ・CDNなし・file:// 直開き**・Chrome/Chromium 前提（File System Access）。
- ヘッダ操作バー：`ファイルを開く`（D&D可）／`更新`／`編集`／`EN｜日本語`／右に件数サマリ＋メタ（📄ファイル名・📅本日・💾保存状態）。
- **i18n**：`I18N` テーブルに ja/en を集約（データは翻訳しない）。
- **フィルタバー**（表示専用・データ不変・localStorage 記憶）：状態（未決／対応中／保留／完了：既定 全ON）／優先度（高／中／低）／担当（ドロップダウン・複数選択・**`actions[].assignee` に出てくる全員から動的収集**。課題は行動担当のどれかが ON なら表示）／`期限超過のみ`。軸内OR・軸間AND。
  **粒度**：状態／優先度／期限超過のフィルタと並び順は**ブック共通**、担当の候補と折りたたみの開閉は**シートごと**。右上の件数は**開いているシート**。
- **備考（note）**：常時表示せず、詳細末尾に `備考` の印（帯より薄い塗り）。**ホバーでツールチップ／クリックで吹き出しを固定**（中のURLを押せる・外側クリックと `Esc` で閉じる）。**たたんだ時は印も出さない**。編集モードは従来どおり textarea。
- **折りたたみ**：**タイトルのセルをクリック**で 1行 ⇄ 全文。たたんだ時の詳細列は**次の一手1行**（`未 9/11 資料作成、内部Rv 担当：ぴぐお/Aさん`・無ければ空欄）。**タイトル列の見出しの `▼/▶`** で全展開／全たたみ。
- **並び替え**：`No（データ順）／期限／優先度` のセグメント（表示専用・localStorage）。
- **更新期間**：メタ行の `更新期間 9/1〜9/7` から `star.from`／`star.to` を編集（`to` 空＝本日まで）。入力欄のラベルも `更新期間`。**データを書き換える操作**なので編集モードのみ。
- **簡素表示トグル**（タイトルクリックで「課題」だけにする）は wbs と同じ動機で入れる（安価なら）。
- 配色：CUD 配慮（Okabe-Ito）。状態は色＋ラベル（形・文字）で冗長化。優先度 高＝赤系・中＝無色・低＝グレー。期限超過＝赤字。**完了行＝タイトルに取り消し線＋行をグレー**（取り消し線を廃止したのは**詳細の中**だけ。一覧としての完了の示し方は従来どおり）。
- **詳細の中の表現規則（2026-09-07 決定）**：役割ごとに**1種類だけ**——帯＝**塗り**／★＝**黒の記号**／済・未＝**文字の濃淡**。**枠線は優先度・状態のバッジ専用**。詳細の中で 塗り・枠・取り消し線・文字サイズの差 は使わない。序列は **帯 ＞ ★ ＞ 備考の印 ＞ 済 ＞ 未**。**★は全箇所で黒**（行動行・タイトル・タブ・右上の `★ 更新 N`）。

### 4.2 編集モード（wbs の保存パスを**そのまま移植**・聖域）
- `編集` ON → File System Access で `issue.json` を選び直し（ジェスチャー再試行／選択時切り詰めへの**即時書込**／保存キューの直列化／mtime 外部変更検知／`InvalidStateError` は1拍おいて1回だけ再試行／パース成功後にハンドル差替／未保存時の離脱確認）。**wbs_viewer.html の `ensureWritable`／`writeNow`／`queueSave`／`flushSaves`／`loadFromHandle`／`openPicker`／`refresh` を流用**し、挙動を変えない。
- 保存時に除外するのは内部派生値（`_calc` 等）のみ。**`_` 始まりのユーザーキーは保持**。
- インライン編集：`title`／`priority`（select）／`due`（ISO テキスト＋📅・短縮入力 `611`・`6/11` は wbs から流用）／`ifIgnored`・`ifDone`・`closeWhen`・`note`（textarea・改行保持）。
- 行動（actions）：`＋` 追加（末尾）／`done` チェック（済⇄未）／日付・本文・担当の編集／`✕` 削除／`▲▼` 並べ替え／`wbs` タグ編集。
- 状態遷移ボタン（1クリックで事実を書く＝片手落ち防止）：
  - `決定を記録`：`decision = { at: 今日, text: 入力 }`
  - `保留`：フォーム（reason 3択・detail・resumeWhen）→ `pending` セット／`保留解除` → `pending = null`
  - `閉じる`：フォーム（how 3択・note）→ `closed` セット／`再オープン` → `closed = null`
- `＋課題`：末尾に追加（`id` = 既存最大+1、`opened` = 今日、`priority` = mid）。`✕` 削除（確認あり）。
- **シート操作**：`＋シート`（名前を prompt。**従来形式のファイルは押した時点で `sheets` 形式へ変換**）／タブの `✕`（確認あり・中の課題ごと）／タブの**ダブルクリック**で名前変更。
- **やらない**：ドラッグ&ドロップ／id 振り直し／複数ファイル／通知・外部送信・eval。

### 4.3 コード規律（wbs の `.claude/rules/ai-coding-wbs.md` 準拠）
- ブラウザ標準優先・枯れたAPI優先・セキュリティ検知を誘発する機能は実装しない。
- **テーブル駆動**（`I18N`／`COLS`／`STATES`／`PRIORITIES`／`PENDING_REASONS`／`CLOSE_HOWS`）。同型3回でヘルパー化。
- サイズ警報線：**全体 100KB**（2026-09-07 にシート追加で 80KB から引き上げ）。超えそうなら機能を削る（価値順：表示＞フィルタ＞編集＞並び替え＞簡素表示）。
- 日本語コメントで「なぜ」を残す（wbs のスタイル）。

  - `id` は**シートごと**に一意。シートをまたいで移すときだけ移動先で振り直す。
- **決めた（2026-09-07・作者裁定）**：**備考（`note`）は常時表示しない**。詳細の末尾に `備考` の印（帯より薄い塗り）だけを出し、ホバーでツールチップ、**クリックで吹き出しを固定**する（外側クリック／`Esc` で閉じる）。たたんだ時は印も出さない。編集モードは従来どおり textarea。JSON の `note` は変更なし。

  - **ホバーだけの吹き出しは不採用**：マウスを離すと消えるので、中の URL を押しに行けない。**クリックで固定**する形にした。

- **決めた（2026-09-07・作者裁定・画像比較）**：詳細の中の表現を「**役割ごとに1種類**」に揃える。帯（概要/実績/予定）＝**濃い灰の塗り・枠なし**／★＝**黒の記号**（琥珀色は廃止）／済・未＝**文字の濃淡**（済＝濃い灰の太字・未＝薄い灰）。**枠線は優先度・状態のバッジ専用**。英語UIだけ 済／未 を **☑／☐** にする。
  - 検討した候補＝済／未の**大きさ差**・**取り消し線（一重／二重）**・**☑☐**・判子風の**丸枠／角枠／朱印／塗り**・帯に**枠線**・帯を**濃い塗り＋枠**・帯の**文字拡大**・済に**薄い塗り**。3課題を並べた画像で見比べて上記に収束した。
  - 不採用の理由＝①**取り消し線**は「済＝消す」に読めるが、済んだ行動こそ**報告の中身**なので消すのは逆。②**判子風の枠**は帯より視覚的に強くなり、**序列（帯＞★＞済＞未）が逆転**する。③**枠を多用する**と、優先度・状態のバッジ（枠線を使う）と喧嘩して、どれが分類でどれが状態か読めなくなる。④**薄い塗り**は白背景でほぼ見えず、区別として機能しない。⑤**大きさの差**は行の高さが揃わず、時系列の一覧として読みにくい。
  - **英語だけ ☑／☐** にしたのは、英語圏のチェックリスト文化に合わせるため（`Done`／`Not done` の語を並べるより短く、意味が即座に通る）。日本語は `済`／`未` の1文字が既に定着しているのでそのまま。濃淡の規則は ja/en 共通。

  - 候補＝①`■` のまま ②帯 ③左に色線＋太字 ④下線 ⑤帯＋全幅の下線 ⑥帯＋左右余白の下線 ⑦帯＋左寄せ8割の薄い線。**3課題を並べた画像で見比べて「帯のみ」を採用**。
  - 理由＝①**行頭の記号（★・済・未）と形が違う**ので、区切りと行の中身を見間違えない（`■` は行頭記号の列に紛れる）②**色を足さない**（CUD 配慮・[ADR-0001](../adr/0001-dependency-free-single-file.md) の方針どおり形で区別する）③**線を足すと表の罫線と競合**し、3課題を開くと区切り線が9本になって画面がうるさくなる。

  - **期間は JSON に持つ**（トップレベル `star`。`to` 省略＝本日／無ければ直近7日）。表示の都合ではなく**報告する人と読む人・AIが同じ★を見る**ためで、派生値ではなく**設定**として扱う（→ [ADR-0008](../adr/0008-facts-only-derived-status.md) の例外）。
