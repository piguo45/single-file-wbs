# 依存タブ（構造の軸）設計メモ — brief-deps v0.2

> v0.1（2026-09-18・案F＝○ごとの可動域の線）を、動くモック第1〜2版の実機確認と敵対検証を経て **v0.2（案G′＝方眼紙・自動配置）** に改訂。課題は `wbs_roadmap.json` の #66。
> 図：[`deps-mock-grid.png`](deps-mock-grid.png)（案G′・○の直径＝マス・ゴム線）／旧：[`deps-mock-picker.png`](deps-mock-picker.png)・[`deps-mock-labels.png`](deps-mock-labels.png)

## 1. 位置づけ
- 右ペインの3つ目のタブ「**依存**」。時間（ガント）・進捗（出来高）に続く**4つ目の軸＝構造**（順序・鎖・クリティカルパス）。
- **時間・進捗は見るだけ。依存タブは右ペインで唯一の「見る＋編集」の面**（図に載せる・結ぶ／外す・置く）。
- **予定（日付）はこのタブでは動かさない**（左表の訂正／`↷` リスケフォームのまま）。依存を知った「後続もずらす」提案は `↷` フォーム側に足す（別課題）。
- 見た目の手本＝情報処理試験のアローダイアグラム（○・直線・日数・太い経路）。ただし **○＝作業**（試験の図は○＝結合点・矢印＝作業）。○＝作業なのでダミー作業は不要。

## 2. データ
| キー | 置き場 | 意味 | 性格 |
|---|---|---|---|
| `_deps` | 葉 | 前工程の id の配列。`[]`＝図に載るが前工程なし。**キーがある＝図に載る** | 事実（つながり）。ビューアが読む `_` キーの4つ目 |
| `_pos` | 葉 | `[列, 行]`（方眼の整数）。**手で置き直した○にだけ付く**。無ければ自動配置 | 設定（見た目の例外の記録）。AI は書かない・読まない |
- 対象は**葉だけ**。集計ノードは○にしない。v1 は **同一案件内・FS（終了→開始）のみ**。
- 派生値（余裕・クリティカルパス・違反・段）は JSON に書かない。
- 後方互換：どちらも省略可。版は **v2.1.0**。
- 参照の追従：**id の変更・葉の削除・集計化で `_deps` の参照を付け替える／消す**（製品の id 変更処理に追加）。切れた参照は図に破線で出し、`scripts/check.py` がエラー（循環もエラー）。

## 3. 画面（案G′・決定）
| 要素 | 決定 |
|---|---|
| 方眼紙 | 右ペイン全幅（**左表は隠す**・時間／進捗に戻すと復帰）。フィルタバーは依存タブでは畳む（効かない） |
| ○ | 作業。**直径＝1マス**。中に番号、**マスの下に名前**（全角 8〜10 字で「…」・全文はホバー） |
| 配置の規則 | **○の周りは必ず1マス空く**（吸着先は1マスおき・上下左右斜め）。設定にせずルールとして固定 |
| 自動配置（既定） | 段＝トポロジカル順（前工程の段＋1）／段の中は**重心法で交差を減らす**（左右数回往復）／1マスおきの格子に列＝段・行＝並び順で置く。決定的（同じ入力→同じ絵） |
| 手動配置（例外） | ドラッグで置き直し → その○に `_pos`。「整列」＝**全部**（`_pos` を消して自動）／**新規だけ**（`_pos` 無しの○を空きに置く） |
| 矢印 | 依存だけ。**直線**（前の○の縁→後の○の縁）。**上に前の作業の日数**（§5 の定義）。数字は根元側 1/3 に置き、交差付近は逃がす。既定は薄く、選択した○の矢印だけ濃く |
| クリティカルパス | 最長経路の○と矢印を**赤＋太線**。右下に「**最長経路 N 日**」（「クリティカルパス N 日」とは呼ばない＝予定日数と混同させない） |
| ◇ | マイルストーン（案件の**最遅**のもの）。最右列。横に「予定では残り M 日・最長経路との差 M−N 日」 |
| 違反 | ○を赤で塗る。判定は §5。ホバーに理由 |
| 数字・詳細 | 常時は番号・名前・矢印の日数だけ。ホバー（`title`）に 期間／開始→終了／前工程・後続／予定との差 |
| 配色 | 新色なし。赤＝CP（輪＋太線）／赤の塗り＝違反／既存の遅延赤と**形で区別**して配色監査に登録 |
| ズーム | 50／75／100%（30 個超で横に広がる対策） |
| 導線 | ○のホバー「時間タブで見る」→ 時間タブの該当行へジャンプ（既存の `gotoWbs`） |

## 4. 操作（編集モードのみ・JSON に書く）
| 操作 | 決定 |
|---|---|
| 図に載せる | ヘッダ左端の **「図に載せる」** ボタン → 葉のチェックリスト（フェーズごと・折りたたみ・既定は畳む）。チェック＝`_deps: []`／外す＝キーと参照を消す（依存が付いていれば確認） |
| 結ぶ | ○を押す → **線がカーソルに追従（ゴム線）** → 別の○の上で押す＝前→後。相手にホバーで輪が光る。Esc／空白クリックで取消。循環・自己参照は拒否 |
| 外す | 矢印にホバーで中点に **✕** → 押す（確認なし・Ctrl+Z で戻す） |
| 置く | ○をドラッグ（しきい値あり・少しの動きでは動かさない）→ 1マスおきに吸着・置ける所を薄く光らせる。Ctrl+Z で戻す |
| 整列 | 「整列 ▾」＝全部／新規だけ |
| 予定変更 | **このタブでは行わない**（B4 の二重の意味を避ける） |

## 5. 計算（決定・ビューアが決定論的に）
- **日数＝予定の期間（暦日）**＝`plan.end − plan.start + 1`。矢印の数字はこれ。営業日換算・人日は未決（ホバーに人日を併記）。
- **最長経路**＝`_deps` の有向グラフで日数の和が最大の経路（◇まで）。その経路上の○と矢印が赤。
- **予定との差**＝◇の日付 − 最長経路の開始 − 最長経路の日数（正なら余裕・負なら間に合わない）。
- **違反**＝後続の予定開始 ≤ 前工程の**実質の終了日**（予定終了と実績終了の遅い方。進行中で本日 > 予定終了なら本日）。
- 計算量は葉と矢印の数に比例。

## 6. AI の役割（説明書に足す依頼例と決まり）
- 依頼例①「作業名・備考・紐づく課題（待ち・未決）から前後関係を推定して依存図に載せて」→ AI は `_deps` を書く（`_pos` は書かない）。骨格の鎖だけ・1作業あたり前工程は最大2つ・循環禁止・予定は動かさない・`note` か `_ai` に「AI 推定（根拠）」を1行。
- 依頼例②「2.4 がクリティカルな理由を説明して」→ 読むだけ（図と課題の文面を引く）。
- 依頼例③「#3 の回答が1週間遅れたらリリースは何日ずれるか」→ 読むだけ（依存をたどり、§5 の式で数字）。
- **クリティカルパスの計算は AI 不要**（ビューアの式）。AI の価値は「文脈から依存を見つける」「説明する」「もしも」。計画と課題が同じ JSON にあるから 1 回の読み取りで済む。
- 書いたら `scripts/check.py`。人が図で直せば AI は次からそれを前提にする（往復で壊れない）。
