# 依存タブ（構造の軸）設計メモ — brief-deps v0.1

> 2026-09-18 の作者との壁打ちで決めたことの記録。課題は `wbs_roadmap.json` の #66。実装前のモック段階。
> 図：[`deps-mock-picker.png`](deps-mock-picker.png)（○を置く作業を選ぶ・◇マイルストーン）／[`deps-mock-labels.png`](deps-mock-labels.png)（名前の置き場＝②○の真下）

## 1. 位置づけ
- 右ペインの3つ目のタブ「**依存**」。時間（ガント）・進捗（出来高）に続く**4つ目の軸＝構造**（順序・鎖・余裕）。
- **時間タブ・進捗タブは見るだけ。依存タブは右ペインで唯一の「見る＋編集」の面**（依存を結ぶ／外す、○を動かす）。
- 目玉機能。時間軸は置かない（置くと時間タブの3番目の兄弟になり、顔が同じになる）。

## 2. データ（`_deps`・ビューアが読む4つ目の `_` キー）
- 後続側の葉に `"_deps": ["1.2", "2.1"]`＝「1.2 と 2.1 が終わってから始める」（FS のみ）。
- **○がある＝その葉に `_deps` キーがある**（前工程が無くても `"_deps": []`）。フラグは別に持たない。キーを消せば○が消える（他の葉の `_deps` から参照も消す）。
- 対象は**葉だけ**（集計ノードは○にしない）。他の葉から参照されているのに `_deps` を持たない葉は `scripts/check.py` が警告。
- 持つのは**事実（つながり）だけ**。余裕・クリティカルパス・違反は派生値＝ビューアが計算し、JSON に書かない。
- 後方互換：省略可。既存の `wbs.json` はそのまま開ける。版は **v2.1.0**（MINOR）。
- AI ネイティブ：「2.3 を依存図に載せて」→ `_deps: []`／「2.3 は 1.4 の後」→ `_deps: ["1.4"]`。依存の推定（作業名・備考から下書き）は将来の依頼例。

## 3. 画面（決定）
| 要素 | 決定 |
|---|---|
| ○ | 作業（葉）。中に番号、**真下に名前**（全角 8〜10 字で切って「…」・全文はホバー）。x＝工程順の段（トポロジカル順）、段の中は日付順 |
| 線 | ○の左右に伸びる**「開始日として選べる範囲」**。左端＝前工程の終了の翌日、右端＝後続に間に合う最も遅い開始日（後続の開始の前日から期間ぶん逆算。後続が無ければマイルストーンの前日）。目盛りは日（月曜が長い）。**○は自分の線の上に乗る**＝○の位置がいまの開始日。表示は 22 日ぶんまで、超えは「…」 |
| 余裕 | 線の長さ＝余裕（フロート）。**余裕 0 ＝線なし＋赤い輪＝クリティカルパス** |
| 矢印 | **依存だけ**（並行できる作業の間には引かない）。曲線。既定は薄く、**選択した○の関係だけ濃く**（既定を「選択時だけ表示」にする案も可・設定で切替） |
| ◇ | マイルストーン（案件の `milestones`）。後続の無い○は◇へ薄い線。線の右端の根拠 |
| 数字 | 開始・終了・日数・余裕は**常時出さない**。ホバーのツールチップ（`title`・ブラウザ標準）に「番号 名前 N日／開始 → 終了／余裕（フロート）N日：いつ〜いつの間で開始できる／前工程・後続」 |
| 左表 | **依存タブでは左の情報表を隠し、右ペインを全幅に使う**（行が○と対応しないため並べると雑音）。作業一覧の役目は「○を置く作業を選ぶ」チェックリスト（折りたたみ可・既定は畳む）。凡例は「?」ホバー。時間／進捗に戻すと左表が復帰（2026-09-18・動くモック第1版の実機確認で決定） |
| 配色 | 色を増やさない。CP＝赤い輪（意味色「遅れ／危険」）、矢印＝グレー、選択＝既存のアクセント青。配色監査を通す |

## 4. 操作（編集モードのみ・JSON に書く）
1. **○を置く作業を選ぶ**：タブ左のチェックリスト（フェーズごと・葉だけ）。チェック＝`_deps: []` を足す／外す＝キーと参照を消す（依存が付いていれば確認）。図の○の ✕ でも外せる。
2. **依存を結ぶ**：○を押して別の○を押す＝A→B（B の `_deps` に A）。循環・自己参照は拒否。**B の開始が A の終了より前なら「B（と後続）を A の終了の翌日以降にずらしますか」**＝ずらす（波及リスケ・理由は自動記録）／やめる（結ばない）。**違反した依存は作れない**（ガードレール）。矢印を押す→「外す」。
3. **○を動かす**：○を選ぶ → 線の目盛りにカーソル＝日付が出る → クリック＝○がその日へ（期間は維持・**線の外には出せない**）→ 既存のリスケフォーム（理由）→ 確定で `plan` 更新＋`_planLog` 追記。
4. **前工程が実際に遅れた時**：後続の線の左端が右へ動き、○が線からはみ出す＝赤で「影響あり」。「後続 N 件をずらす」を**提案**（自動では動かさない・確定で各葉に「#A の遅れの波及」と理由を記録）。
- 日付セルの直接編集（訂正）と `↷` フォームは左表の編集モードに従来どおり残す。`↷` フォームは `_deps` を知り「後続 N 件に違反が出ます → 同じ日数ずらす」を出せるようにする（別課題）。

## 5. 計算（CPM・葉の数に比例）
- 前向き走査：最早開始 ES(B)＝max(前工程の終了)+1（前工程なし＝現在の予定開始）。
- 後ろ向き走査：最遅終了 LF(A)＝min(後続の開始)−1（後続なし＝マイルストーン−1）。最遅開始 LS＝LF−期間+1。
- 余裕＝LS−ES（日）。0 ＝クリティカルパス。違反＝現在の開始 < ES。
- 暦日で計算（営業日換算は v2 以降の論点）。
